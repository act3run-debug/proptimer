# Автотесты «Пропорционального таймера»

Приложение — один файл [`index.html`](../index.html) без сборки и зависимостей.
Тесты **не копируют** код приложения: они извлекают inline-`<script>` прямо из
`index.html` и выполняют его в [jsdom](https://github.com/jsdom/jsdom), поэтому
всегда проверяют актуальную страницу.

## Запуск

```bash
npm install     # нужен только jsdom (dev-зависимость)
npm test        # node --test  → 489 тестов (~50 с)
```

Требования: Node.js 20+ (проверено на v24.19.0 и jsdom 26; jsdom 30 требует Node 22+).
Скрипт `npm test` запускает `node --test` без пути: форма `node --test tests/` на
Node 22+ воспринимает каталог как файл и падает. Часовой пояс процесса стенд
фиксирует на UTC сам (`harness.js`), поэтому результаты не зависят от настроек машины.

Пакеты в песочнице между сессиями не сохраняются — после восстановления
окружения `npm install` нужно выполнить заново.

Как устроено: расписание **не хранит интервалы** — оно выводится из Целей (`ScheduleModel.computeLayout`): длительность дня `D = Конец − Начало` (равные — 24 ч), узлы идут подряд от «Начала» в сохранённом порядке по времени, длительность = Цель × D. Поэтому «основной экран → конструктор» синхронизируется сразу и без отдельной механики. Окно работает с черновиком (`DayDraft`) и переносит его на основной экран только по «Сохранить» (`DayDraft.commit`).

Допущения там, где требования неоднозначны (см. `conspect.md`, раздел «Конструктор дня»): «Конец» по умолчанию остаётся пустым полем и трактуется как 00:00; «прилипание» «Конца»/«Начала» к концу активности включается только после первого сохранения из конструктора; «В группу» сдвигает сущность целиком (длительность сохраняется); удаление в конструкторе делит время пропорционально, кроме крайних элементов при единственном промежутке (вытягивается сосед).

## Как устроен стенд

- **Часы под контролем.** `window.Date.now` заменён на управляемый, время
  двигается вручную (`ctx.clock.advanceSec(...)`), поэтому сценарии
  детерминированы. Опорная точка `T0` — ближайший целый час UTC *в будущем*:
  приложение трактует «Конец» (ЧЧ:ММ) через `Intl.DateTimeFormat`, а
  форматтеры `Intl` не обращаются к `Date.now()` и не подменяются, поэтому
  дата в тестах обязана совпадать с реальной.
- **Тик вместо `setInterval`.** `window.setInterval` перехватывается: фоновый
  пересчёт (200 мс) в тестах вызывается вручную — `ctx.tick()`.
- **Сеть отключена.** `fetch` заглушен и записывает обращения; ключ
  синхронизации не задан, поэтому `CloudSync.isActive()` ложно и облако в
  тестах не участвует (проверяется отдельно).
- **Окна закрываются.** Все созданные окружения попадают в реестр, и хук
  `after(closeAll)` закрывает их по окончании прогона — иначе `node --test`
  не завершается.

## Хелперы стенда для дерева

Появились в `tests/harness.js` вместе с группировкой:

- `ctx.addFolder(name, parentNode)` — создать папку в модели и перерисовать дерево;
- `ctx.moveToFolder(nodeId, folderId)` — перенести узел (`null` — в корень);
- `ctx.folderEl(id)`, `ctx.folderHeader(id)`, `ctx.folderChildrenEl(id)` — элементы
  папки. **Важно:** `folderEl` содержит и карточки детей, поэтому поиск кнопок и
  полей папки нужно ограничивать шапкой — `folderHeader`;
- `ctx.flat()` — плоский порядок дерева `[{kind, id, depth}]` (DFS), `ctx.rootOrder()`
  — только корневые id;
- `ctx.shareInput/shareRow/shareValue`, `ctx.moveButton(node, "up"|"down")`,
  `ctx.sumTargets()`;
- `ctx.card(...)`, `ctx.shareInput(...)` и другие «карточные» хелперы принимают
  как сущность, так и её id (`idOf`);
- `ctx.isVisible(el)` — видимость с учётом предков: `getComputedStyle` в jsdom не
  знает про `display: none` у родителя, а свёрнутая папка скрывает содержимое
  именно так.

Две грабли, которые стоили отладки:

1. **Массивы из области jsdom.** `TreeModel.flatten()`/`root()` возвращают массивы,
   созданные внутри окна jsdom, и `assert.deepEqual` (strict) сравнивает их с
   обычными массивами Node как «Values have same structure but are not
   reference-equal». Хелперы `flat()`/`rootOrder()` оборачивают результат в
   `Array.from`, а в тестах списки из `getTimers()`/`childrenOf()` нужно
   разворачивать так же (`[...]` или `Array.from`).
2. **Карточка не находится по id.** `AppState.getTimerElement` — это
   `getElementById`, поэтому карточка, вынутая из документа, становится
   «несуществующей». Так тест вскрыл настоящий баг рендера: `renderTree()` брал
   контейнер детей папки через `document.getElementById`, а только что созданная
   папка ещё не прикреплена к документу — при одиночном проходе рендера дети не
   отрисовывались, а их карточки удалялись как «лишние» (воспроизводилось на
   приёме дерева из облака). Исправлено в `index.html`: контейнер детей берётся
   из самого элемента папки.
