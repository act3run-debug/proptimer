# Автотесты «Пропорционального таймера»

Приложение — один файл [`index.html`](../index.html) без сборки и зависимостей.
Тесты **не копируют** код приложения: они извлекают inline-`<script>` прямо из
`index.html` и выполняют его в [jsdom](https://github.com/jsdom/jsdom), поэтому
всегда проверяют актуальную страницу.

## Запуск

```bash
npm install     # нужен только jsdom (dev-зависимость)
npm test        # node --test tests/  → 135 тестов
```

Требования: Node.js 20+ (проверено на v20.20.2 и jsdom 26; jsdom 30 требует Node 22+).

Пакеты в песочнице между сессиями не сохраняются — после восстановления
окружения `npm install` нужно выполнить заново.

## Состав

| Файл | Что проверяет | Тестов |
| --- | --- | --- |
| `tests/harness.js` | Стенд: jsdom, извлечение `<script>`, фейковые часы, перехват `setInterval`, хелперы (`setup`, `tick`, `addTimer`, `click`, …) | — |
| `tests/auto-away.test.js` | Автоматический режим «Отошёл»: взвод/снятие, списание простоя из планов, заморозка на время отсчёта, ролловер сессии, перезагрузка и авто-пауза, отсутствие кнопки в интерфейсе | 46 |
| `tests/regression.test.js` | Остальная логика без изменений: отсчёт, сброс, ручной ввод счётчиков, операции над задачами, рекомендации и приоритеты, суточный сброс, хранилище и битые данные, утилиты, DOM, модальные окна | 51 |
| `tests/integration.test.js` | Сквозной сценарий «день из жизни», целостность `index.html` (синтаксис, CRLF, состав классов, разметка, версия) | 8 |
| `tests/compact-mode.test.js` | Компактный режим: карточки свёрнуты по умолчанию, состав видимых строк (`getComputedStyle`), стрелка ▼/▲ и её делегирование, отсутствие побочных эффектов на модель/облако, работа свёрнутой карточки, жизненный цикл состояния | 30 |

## Как устроен стенд

- **Часы под контролем.** `window.Date.now` заменён на управляемый, время
  двигается вручную (`ctx.clock.advanceSec(...)`), поэтому сценарии
  детерминированы. Опорная точка `T0` — ближайший целый час UTC *в будущем*:
  приложение трактует «Конец» (ЧЧ:ММ) через `Intl.DateTimeFormat`, а
  форматтеры `Intl` не обращаются к `Date.now()` и не подменяются, поэтому
  дата в тестах обязана совпадать с реальной.
- **Тик вместо `setInterval`.** `window.setInterval` перехватывается: фоновый
  пересчёт (200 мс) в тестах вызывается вручную — `ctx.tick()`.
- **Сеть отключена.** `fetch` заглушен и записывает обращения; ключ
  синхронизации не задан, поэтому `CloudSync.isActive()` ложно и облако в
  тестах не участвует (проверяется отдельно).
- **Окна закрываются.** Все созданные окружения попадают в реестр, и хук
  `after(closeAll)` закрывает их по окончании прогона — иначе `node --test`
  не завершается.

## A/B-проверка отсутствия регрессий

`tests/regression.test.js` намеренно не завязан на авто-«Отошёл», поэтому его
можно прогнать против исходной версии страницы:

```bash
mkdir -p /tmp/baseline
git show 504ffe7:index.html > /tmp/baseline/index.html      # версия до правок
INDEX_HTML=/tmp/baseline/index.html node --test tests/regression.test.js
```

Ожидаемые результаты:

| Набор | Исходный код (`504ffe7`) | Текущий код |
| --- | --- | --- |
| `regression.test.js` | **51 / 51 pass** | **51 / 51 pass** |
| `auto-away.test.js` | 7 pass / 39 fail | **46 / 46 pass** |
| `integration.test.js` | 3 pass / 5 fail | **8 / 8 pass** |

То есть регрессионный набор зелёный на обеих версиях (поведение не сломано), а
тесты нового поведения падают на исходном коде и проходят на новом — значит они
действительно проверяют авто-«Отошёл», а не что-то тривиальное.

## A/B для компактного режима

Базовая версия — последний коммит до правки (`a3188dc`):

```bash
mkdir -p /tmp/baseline
git show a3188dc:index.html > /tmp/baseline/index.html
INDEX_HTML=/tmp/baseline/index.html node --test tests/regression.test.js
INDEX_HTML=/tmp/baseline/index.html node --test tests/compact-mode.test.js
```

| Набор | Исходный код (`a3188dc`) | Текущий код |
| --- | --- | --- |
| `regression.test.js` | **51 / 51 pass** | **51 / 51 pass** |
| `compact-mode.test.js` | 1 pass / 29 fail | **30 / 30 pass** |
| `auto-away.test.js`, `integration.test.js` | — | **54 / 54 pass** |

Единственный тест нового набора, который проходит и на исходном коде —
«„Приоритет“ виден и заполняется после расчёта рекомендаций»: он проверяет
работоспособность поля, а не сворачивание (в исходной версии поле тоже видно).

В `regression.test.js` ослаблено ровно одно утверждение — `card.className`:
вместо строгого равенства `"timer-container"` теперь
`assert.match(card.className, /^timer-container( collapsed)?$/)`. Формула
принимает оба варианта, поэтому набор остаётся пригодным для A/B-прогонов.
